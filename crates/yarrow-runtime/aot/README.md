# yarrow-runtime-aot

Ahead-of-time (AOT) static library for the Yarrow runtime.

## Overview

`yarrow-runtime-aot` is a **static library** that provides runtime support for **ahead-of-time compiled** Yarrow programs. It exposes stable, linker-visible symbols that compiled Yarrow code can call at runtime.

## Purpose

When compiling Yarrow to native executables (AOT compilation), the resulting binary needs:

1. **Runtime initialization** - Set up the host heap and global state
2. **Host function access** - Call standard library and FFI functions
3. **Memory management** - Allocate and manage Yarrow values
4. **Error handling** - Handle runtime errors consistently

`yarrow-runtime-aot` provides all of this in a **statically linkable** form.

## Features

### Exported Symbols

The library exports the following symbols (with the `aot-exports` feature):

| Symbol                 | Description                                                |
| ---------------------- | ---------------------------------------------------------- |
| `yarrow_aot_init`      | Initialize the runtime (call before executing Yarrow code) |
| `yarrow_aot_shutdown`  | Clean up the runtime (call before program exit)            |
| `yarrow_aot_alloc`     | Allocate a Yarrow value on the heap                        |
| `yarrow_aot_dealloc`   | Deallocate a Yarrow value                                  |
| `yarrow_aot_call_host` | Call a host function by ID                                 |
| `yarrow_aot_panic`     | Trigger a runtime panic                                    |
| `yarrow_aot_host_fn_*` | Individual host function implementations                   |

### Host Function Registry

All standard library host functions are exported with stable names:

```
yarrow_aot_host_fn_std_io_write_line
yarrow_aot_host_fn_std_io_read_line
yarrow_aot_host_fn_std_math_add
yarrow_aot_host_fn_std_mem_alloc
```

## Usage

### In Cargo.toml

```toml
[target.'cfg(not(test))'.dependencies]
yarrow_runtime_aot = { path = "crates/yarrow-runtime/aot" }
```

Or with features:

```toml
[dependencies]
yarrow_runtime_aot = { path = "crates/yarrow-runtime/aot", features = ["aot-exports"] }
```

### Linking with AOT Compiled Code

When using `cranelift-object` to emit object files:

```rust
use object::{Object, ObjectSymbol};

// Your Yarrow compilation code...
let obj = Object::new();

// Link with yarrow-runtime-aot
obj.add_symbol(ObjectSymbol::Global {
    name: "yarrow_aot_init".to_string(),
    value: 0,  // Will be resolved by linker
    size: 0,
    kind: object::SymbolKind::Text,
    scope: object::SymbolScope::Linkage,
    weak: false,
    section: object::SectionIndex(0),
});
```

### Initialization in C

For C programs linking with AOT-compiled Yarrow:

```c
#include <stdint.h>

// Declare the runtime initialization function
extern void yarrow_aot_init(void);
extern void yarrow_aot_shutdown(void);

int main(int argc, char** argv) {
    // Initialize the Yarrow runtime
    yarrow_aot_init();

    // Call your compiled Yarrow code
    yarrow_main();

    // Clean up
    yarrow_aot_shutdown();

    return 0;
}
```

### Calling Host Functions

From compiled Yarrow code, host functions are called through the AOT dispatcher:

```c
// Generated by yarrow-core's AOT compiler
extern int64_t yarrow_aot_call_host(uint32_t func_id, void* args);

// Call std.io.write_line with a string argument
yarrow_aot_call_host(1, &my_string_value);  // func_id=1 = std.io.write_line
```

## Building

```bash
cargo build -p yarrow_runtime_aot --release
```

The static library will be available at:

- Linux/macOS: `target/release/libyarrow_runtime_aot.a`
- Windows: `target/release/yarrow_runtime_aot.lib`

## Linking

### With GCC/Clang

```bash
gcc -o my_program my_program.o -Ltarget/release -lyarrow_runtime_aot -lstdc++
```

### With Rust

```rust
#[link(name = "yarrow_runtime_aot", kind = "static")]
extern "C" {
    fn yarrow_aot_init();
    fn yarrow_aot_shutdown();
}

fn main() {
    unsafe {
        yarrow_aot_init();
        // ... call Yarrow code ...
        yarrow_aot_shutdown();
    }
}
```

## Error Handling

The AOT runtime provides error handling through:

1. **Return codes** - Functions return error codes
2. **Error callbacks** - Register a callback for error reporting
3. **Panic handler** - Custom panic behavior

```c
extern void yarrow_aot_set_error_handler(void (*handler)(const char* message));

extern void yarrow_aot_set_panic_handler(void (*handler)(void));
```

## Memory Management

The AOT runtime provides a **simple allocator** for Yarrow values:

```c
// Allocate a value (returns a pointer)
void* value = yarrow_aot_alloc(sizeof(MyValue));

// Deallocate a value
yarrow_aot_dealloc(value);
```

For production use, you may want to:

1. Replace the allocator with your own
2. Integrate with the system allocator
3. Use a custom allocator for your use case

```c
// Set a custom allocator
extern void yarrow_aot_set_allocator(
    void* (*alloc)(size_t size),
    void (*dealloc)(void* ptr)
);
```

## Integration with yarrow-core

When compiling with `yarrow-core` for AOT:

```rust
use yarrow_core::{Compiler, Session, SessionConfig, EmitMode};

let config = SessionConfig {
    emit_mode: EmitMode::Object,
    aot_mode: true,
    ..Default::default()
};

let mut session = Session::new(config);
let mut compiler = Compiler::new(&mut session);

// Compile to object file
let obj = compiler.compile_to_object("my_program.yar")?;

// Write the object file
std::fs::write("my_program.o", obj.emit()?)?;
```
